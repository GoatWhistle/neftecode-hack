# CUTPOINT — перестройка фронтенда: схема расчёта

Третий круг. Заменяет вертикальную ленту из восьми цветных секций на **технологическую
схему расчёта**: узлы-этапы, соединённые стрелками, уложенные змейкой в три строки.
Нажатие «Пуск» запускает настоящий прогон; схема проигрывает его по мере прихода событий.
Любой узел раскрывается в панель с временем, характеристиками и всей работой этапа.

Источники направления: два референса руководителя (ряд карточек 01–06 со стрелками;
тёмная схема «контур данных / контур решения» из `context/data-flow.html`) и его требования:
не одна строка, а змейка; убрать разноцветные подложки; раскрывать этап; «интересная
и крутая визуальная штука», но здравый продукт без ИИ-слопа.

Контекст для скиллов: `PRODUCT.md` (регистр product), `DESIGN.md` (монохром, шрифт, радиусы).

Ограничения, действующие на любом шаге (перенесены из `FRONTEND_TODO.md`, удалённого
при чистке документации — сам файл был журналом сессий, но эти правила остаются в силе):

1. **Честность интерфейса выше красоты.** Оговорки происхождения чисел, «живая модель
   не участвовала», «данных не передавали», предупреждения об отсутствии срезов не
   удаляются ради вида. Пустой блок пишет, что данных нет, а не выглядит заполненным.
2. **Рисовать только то, что есть в payload.** Не выдумывать числа, не имитировать данные.
3. Ноль комментариев в коде. TypeScript, именованные экспорты, файлы ≤ 250 строк.
4. Никаких новых npm-зависимостей и внешних запросов в рантайме — сеть завода закрыта.
5. Движение 150–600 мс, без спиннеров, параллакса, пружин, отскоков;
   обязательный `@media (prefers-reduced-motion: reduce)`.
6. Контраст не ниже WCAG AA, считать цифрами.
7. Не вешать `overflow: hidden`, `isolation`, `contain`, `transform`, `filter` на контейнеры
   схемы и их предков — это ломает измерение геометрии стрелок.
8. Порт 8765 занят сервером пользователя: не занимать, не убивать, не перезапускать.
9. Git — только по явному разрешению пользователя. Python в `src/neftecode/` — только если
   без этого никак.
10. **Никакого ИИ-слопа.** Это здравый взрослый продукт для оператора НПЗ. Запрещены
   градиентные заливки ради красоты, свечения, glassmorphism, эмодзи в интерфейсе,
   декоративные частицы, фальшивые «терминальные» логи, печатающийся текст, пульсирующие
   ореолы, бессмысленные счётчики и прогресс-бары, пафосные формулировки. Анимация
   объясняет смену состояния, а не развлекает.

## 0. Решения, принятые до начала работ

Каждое можно оспорить, но не молча: если агент отступает — пишет почему в отчёт.

### 0.1 Светлая тема остаётся основной

Референс руководителя тёмный, но это тёмный вариант `context/data-flow.html`, который
по умолчанию светлый и переключается системной темой. Основная сцена — проектор в комнате
защиты: тёмный фон на проекторе теряет контраст, светлый читается. Логотип, `DESIGN.md`
и вся система мер построены на vellum/carbon. Тёмная тема — отдельная финальная фаза Ф6
после показа руководителю, через `prefers-color-scheme` и явный переключатель;
токены для неё уже есть в `data-flow.html` (`--paper #11171A`, `--surface #182126`,
`--ink #E2E8E5`). **Это единственный пункт, который стоит подтвердить у руководителя
до Ф6; до этого он ничего не блокирует.**

### 0.2 Восемь подложек удаляются целиком

`--band-*`, `--band-line-*`, `--band-field-*`, `--band-hover-*`, файл `bands.css`,
атрибут `data-band` — всё вон. Иерархия строится на монохроме: vellum → paper → carbon,
рамка сплошная / пунктир / двойная, начертание 300/500/600.

### 0.3 Один акцент — янтарь логотипа

`--accent: #c8761a` (уже в `Logo.tsx`). Значение «сейчас»: рамка и номер текущего узла,
стрелка, которая сейчас рисуется, слой агентов (как жёлтый узел LLM у руководителя).
Контраст `#c8761a` на vellum ≈ 2,97 — **годится только для рамок ≥ 2px и заливок,
не для текста.** Для текста — `--accent-ink: #8a4d0f` (≈ 5,8 на vellum; пересчитать
в реализации, значения ориентировочные). Семантические `--pass / --fail / --unknown`
остаются только на состоянии, как сейчас.

### 0.4 Змейка настоящая, бустрофедон

Строка 1 слева направо, строка 2 справа налево, строка 3 слева направо. Стрелки короткие
и непрерывные, без длинной возвратной линии. Номера на карточках ведут глаз, поэтому
чтение «6 ← 5 ← 4» не путает. Если в аудите окажется, что путает, — запасной вариант:
все строки слева направо с угловым коннектором справа вниз-налево (как у руководителя),
цена — одна длинная линия на строку.

### 0.5 Схема показана до пуска

Все узлы в состоянии «ожидает» (пунктир, приглушённый текст) видны под формой условий
с первой секунды. Зритель видит маршрут до того, как нажал «Пуск». Это и есть
«одна схема всей системы» из `data-flow.html`.

### 0.6 Анимация — это реальный ход расчёта

Никакой отдельной «красивой прокрутки» с выдуманным темпом. Узлы загораются по событиям
сервера через существующую очередь раскрытия (`run/revealQueue.ts`). Выдержка между
шагами поднимается с 260 до **450 мс**, чтобы стрелка успевала прорисоваться (320 мс)
и узел — включиться (130 мс). Время на узлах остаётся измеренным (`<0,1` для этапов,
прошедших за миллисекунды) — темп показа и измеренное время различаются, и об этом
говорит существующая оговорка «раскрыт из payload — это не длительность расчёта».

Повтор («▶ ещё раз» после конца прогона) проигрывает **записанную** ленту событий
этого же прогона со сжатием пауз агентов; на экране подпись «повтор записи, паузы сжаты».

### 0.7 Что раскрывается, а что нет

| Узел | Раскрытие | Почему |
|---|---|---|
| 0 Условия | да, компактно: `ConfigBrief` + «Новый прогон» | форма до пуска, после — сводка |
| 1 Состояние | да | уставки, рецепт, запасы, происхождение |
| 2 Доверие к данным | да | источники, возраст замеров, вердикт |
| 3 Кандидаты | да | воронка отсева, раунды, семейства |
| 4 Прогноз | да | запасы по свойствам, траектория, упреждение |
| 5 Выбор | да | альтернативы, чем отличаются, устойчивость, offspec |
| 6 Gate | да | матрица 129 проверок, запас по уставкам |
| 7 Агенты | да | диалог, инструменты, бюджеты, вето, мнения |
| 8 Решение | **нет — всегда открыт** | это итог; постоянная панель «Итог» под схемой |
| Входы (сценарий, модель) | нет | структурная подпись, данных на раскрытие нет |
| Исходы hold / recommend / refuse | нет, клик = прокрутка к «Итогу» | это ответ, а не этап |

### 0.8 Левая рейка удаляется

Схема сама является навигатором. Вместо рейки — тонкая липкая полоса состояния,
появляющаяся, когда схема ушла за верх экрана: часы, текущий этап, «к схеме ↑», стоп.

### 0.9 Что нельзя потерять (перечень оговорок честности)

Все они существуют сейчас и обязаны существовать после перестройки, дословно или по смыслу:
подпись источника этапа (`stageSource`: отметка сервера / раскрыт из payload);
полоса провайдера «живая модель» / «детерминированная политика» / `fallback` с причиной;
бейджи происхождения чисел (`OriginBadge`); тексты `Empty` («не передавалось»);
подпись под `MarginBars` об отказе от «процента здоровья»; ступенчатая траектория;
«последний ответ сервера N с назад» при обрыве; «повтор записи, паузы сжаты».

## 1. Информационная архитектура схемы

### 1.1 Узлы

Три вида узлов. Только этапы (`stage`) имеют состояние и время; остальные статичны.

```
kind: stage    — 8 этапов сервера + узел 0 (условия); имеют pending/running/done/failed
kind: input    — внешний вход, пунктирная рамка, без состояния:
                 «Сценарий и срез» (имя сценария, момент, отказ источника — из условий)
                 Узел «Модель прогноза» ОТМЕНЁН: проверено, сервер не шлёт ни имени модели,
                 ни метрик (`Forecast` несёт только траекторию свойства; в `ui.py` полей о
                 модели нет). Узел мог бы нести только статичный текст из README, не связанный
                 с прогоном, — это запрещено п. 2 и п. 10. Вход остаётся один.
kind: terminal — три исхода: hold · recommend_scenario · refuse; загорается один
```

Раскладка на ≥ 1100 px — четыре колонки, три строки, змейка:

```
КОНТУР ДАННЫХ     [вход: сценарий и срез] → [1 Состояние] → [2 Доверие к данным] → [3 Кандидаты] ┐
                                                   ↓ выход ОТКАЗ (нет годного источника)         │
КОНТУР РЕШЕНИЯ    [6 Gate] ← [5 Выбор] ← [4 Прогноз: упреждение 48 ч] ←───────────────────────────┘
                     │  ↑ пунктир: агенты сужают выбор → снова Gate       ↺ у 3: вето сужает поиск, до 3 раундов
СЛОЙ АГЕНТОВ      [7 Агенты · LLM] → [8 Решение] → { hold | recommend_scenario | refuse }
```

Порядок этапов и их смысл соответствуют серверу: прогноз-упреждение считается **до**
выбора и может заменить план (`_look_ahead`, `switched`), поэтому он четвёртый.
Подписи контуров слева от строк — как у руководителя, мелкими капителями с квадратом-маркером
(уже есть `.label` в `stage.css`).

### 1.2 Рёбра

```
flow  — основной ход, сплошная линия со стрелкой; рисуется при переходе к следующему узлу
loop  — петля 3→3 «вето сужает поиск»; подпись становится «раунд N из 3», когда rounds > 1
back  — пунктир 7→6 «сужает выбор → снова Gate»; загорается, когда в трассе есть replans > 0
exit  — пунктир к refuse из 2, 3, 6, 7; всегда виден бледным (это документация системы),
        красным — только если отказ действительно случился на этом узле
```

Таблица выхода по `payload.decision.refusal.kind` (виды взяты из `make_decision.py`,
`decision/lookahead.py`, `agentic/decision.py`):

| kind | узел выхода |
|---|---|
| `data` | 2 Доверие к данным |
| `no_feasible_plan`, `computation_error` | 3 Кандидаты |
| `final_recheck_failed` | 6 Gate |
| `agent_rejected`, `weak_response_failed` | 7 Агенты |
| неизвестный | 8 Решение — не гадать, выход из итога |

Обрыв потока / ошибка сервера (`status: failed`) — красная двойная рамка на реально
шедшем узле (логика уже есть в `useRun.fail`), стрелки дальше не рисуются.

### 1.3 Карточка узла-этапа

Фиксированный размер (около 250 × 128 px на четырёх колонках), содержимое не меняет
высоту — схема не должна дёргаться. Сверху вниз:

```
03                      ← номер, моно, 22px; у текущего — акцент
Кандидаты               ← заголовок, 16px, 500
optimizer · 3 раунда    ← моно-подпись 12px, приглушённая: артефакт этапа (как у руководителя)
                          до пуска — что этап сделает; после — 1–2 главных факта из StageFacts
0,6                     ← время справа внизу, моно; у текущего — живые часы (useLiveClock)
```

Факты берутся из существующего `run/stageFacts.ts` (первые две строки `*Lines`),
а для 7 Агентов — из `agentMeters`/`orchSteps`: «ход 2 из 5 · ждём агента качества 12,3».
Это то самое «видно, что оркестратор решает», без раскрытия карточки.

Состояния карточки (цвет никогда не единственный признак):

| состояние | рамка | номер | слово |
|---|---|---|---|
| pending | 1px пунктир `--line-soft` | приглушён, 400 | ожидает |
| running | 2px сплошная `--accent`, верхняя линия 3px | акцент, 600, мигает `rail-blink` | идёт |
| done | 1px сплошная `--carbon` | `--pass`, 700 | готово / без отметок |
| failed | 3px двойная `--fail` | `--fail`, подчёркнут | отказ |

Единственная бесконечная анимация во всём проекте — мигание номера текущего узла
`steps(1)` 1200 мс (уже принято пользователем). Без ореолов и пульсаций рамки.

### 1.4 Панель раскрытия

Клик по узлу (кнопка `aria-expanded`) открывает панель **под строкой этого узла** на всю
ширину схемы; открыта одна панель. Заголовок панели:

```
3 · Кандидаты — готово · начат на 0,17 с · длился 0,6 с · отметка сервера        [закрыть ×]
```

Тело — существующие компоненты этапов без своей шапки (`Section` перестаёт быть
обёрткой; `stages/*Stage.tsx` возвращают тело). До прихода `payload` тело панели —
`StageLive` + `AgentDialogue` (то, что сейчас в `StageOutline`). Ничего из
визуализаций второго круга не переписывается — переезжает целиком.

Открытие: `grid-template-rows: 0fr → 1fr`, 240 мс, `--ease`; reduced-motion — мгновенно.
Схема под панелью пересчитывает стрелки (ResizeObserver на контейнере).

### 1.5 «Итог»

После события `screen` под схемой появляется постоянная панель «Итог» — тело
`DecisionStage` (вердикт, действия, отказ, объяснение). Это кульминация страницы,
поэтому она не прячется в раскрытие. Клик по исходу-терминалу прокручивает к ней.

### 1.6 До пуска и после

До пуска: логотип → форма «Условия прогона» (с кастомными селектами, как сейчас) →
кнопка «▶ Пуск» → схема в ожидании. После нажатия: форма сворачивается в узел 0
(240 мс, содержимое заменяется сводкой), схема поднимается, начинается прогон.
«Стоп» и Escape — как сейчас. После конца: «▶ Ещё раз» (повтор записи) и «Новый прогон».

### 1.7 Отзывчивость

- ≥ 1100 px — четыре колонки, три строки змейкой.
- 720–1100 px — две колонки, змейка в пять строк; подписи контуров над строками.
- < 720 px — одна колонка, вертикальный ход сверху вниз, стрелки вертикальные,
  петли и выходы — короткие пунктиры сбоку с подписью. Панели раскрытия — под узлом.
- Печать — статичная схема с состояниями через стили рамок, все панели раскрыты,
  стрелки чёрные, акцент → жирная рамка (принцип `print.css` сохранён).

## Карточки участников в панели «Агенты» (2026-09-21)

Руководитель: «на третьем и четвёртом пустоты, особенно если json развернуть — вокруг просто
пиздец», «просмотри каждый блок: всё в нашей системе, логично, без пустот, читаемо, доказуемо,
интересно, вся информация доступна».

**Причина пустот найдена численно.** `.agents { align-items: stretch }` + `.agent

все карточки тянулись до высоты самой высокой, содержимое липло к краям, середина пустовала.

`margin-top: auto`. Замерено: высоты стали 189 / 258 / 209 / 303 / 503 (по содержимому)
вместо одинаковых растянутых; зазор перед подвалом 0–12px.

**Раскрытый JSON рвал ряд.** `.panel__body { max-height: 460px }` — карточка вырастала
до 648px, соседний ряд разъезжался. Внутри сетки участников ограничено до 260px:
раскрытая карточка 449px, ниже самой высокой в ряду (503px), ряд цел.

`TITLES`/`ROLES` — показывались сырые коды и «участник трассы» с прочерком, хотя данные
в трассе есть. Добавлены названия («Агентный слой», «Оценка резервуара»), роли, вердикты
(«выбран план c0159», «решение чувствительно к оценке») и счётчики

### Ходы оркестратора: мёртвые зоны и нумерация

Нумерация ходов шла заново в каждом блоке `.orch`: цикл прерывается консультациями
и возобновляется, поэтому на экране читалось «01 ход из 5» → консультация → снова
«01 ход из 5». Судья видел два первых хода. Введено сквозное смещение (`offset`
в `run/orchSteps.ts`, `moveOffsets` в `AgentDialogue.tsx`) — ходы нумеруются 01…07,
а каждый блок подписан диапазоном: «цикл продолжен, ходы 02–05 · предел 5 шагов
на отрезок».

Формулировка «обращение к модели · политика, без вызова модели» утверждала
одновременно, что обращение было и что вызова не было. Заменена на «ход рассчитан
политикой, модель не вызывалась».

Мёртвые зоны. Тело хода — grid `auto-fit minmax(460px, 1fr)`, на 2560px это три
колонки; у финального хода внутри один `.orch-decision`, он садился в первую
колонку, две оставались пустыми — **1294px**. Ходы-пустышки давали **1575px**.
Введён флаг `lone` (ровно один содержательный блок) рядом с `bare` (ни одного):
`.orch-move--lone:not(:has(.orch-move__tools))` занимает две колонки вместо всех,
`.orch-move--bare` получил `width: max-content`. Замерено на живой странице
на 2560px: максимум **76px** против 1575px. Пустышки сжались до 476 и 392px,
финальный ход — 806px.

Утверждение агента, что панель агентов пуста после завершения прогона, проверено
и не подтвердилось: 7 ходов, 2 консультации, 8 карточек участников. Вероятная

### Итоговые виды этапов 1–8

Две системные причины пустот. Первая — одиночные пояснительные абзацы прямыми
детьми `.stage__body`: растянуты на всю ширину, высота в одну строку, мёртвая зона
1223–1676px на каждом этапе. Соседние примечания собраны в `.notes-rail` и встают
рядом, каждое в пределах меры; ширина ленты зависит от числа примечаний через
`:has(> :last-child:nth-child(n))`, иначе одно примечание растягивало её на три меры.

Вторая — токен `--dense-max: 1600px`: карточные сетки упирались в 1600px внутри
2454px-контейнера, при том что соседние блоки шли на 2464 — рваный правый край.
Снят со стейджевых сеток.

Попутно исправлено: `.origin-legend` (515px) и `.gatebar` (594px) — карточки
с рамкой во всю ширину при содержимом в одну строку, обе переведены на
`width: fit-content`. График прогноза (521px) — вторая колонка `1fr` вдвое шире
подписи; график забирает остаток, подпись ограничена мерой. `.final__verdict`
на этапе 8 — вторая колонка `1fr` тянулась до края при причине в пределах меры.

Замерено на живой странице на 2560px после правок: Состояние 35, Доверие 165,
Кандидаты 63, Прогноз 84, Выбор 188, Gate 91, Агенты 0. Ни одной зоны шире 200px.
Горизонтальной прокрутки нет.

Предыдущий агент на этой задаче применил `columns` к одиночным абзацам — абзац
в 1–3 строки не делится на 4 колонки, а подпись графика разрезалась на фрагменты
и читалась как бессмыслица. Решение откачено: резать текст ради метрики хуже,
чем оставить поле справа.
