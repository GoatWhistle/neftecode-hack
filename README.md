# CUTPOINT

Советчик оператору цепочки АВТ → гидроочистка → смешение дизельного топлива.
Проверяет доступные данные, прогнозирует серу, сравнивает планы и выдаёт рекомендацию,
сохранение режима или объяснённый отказ.

Описание включает доработки 22.09.2026: сравнение условий, карту компромиссов,
профиль тяжести, протокол записи и партийную модель парка резервуаров. Границы
доказательств и ограничения приведены ниже.

Это исследовательский прототип. Он не управляет установкой, а
`commercial_release_allowed=false` запрещает трактовать ответ как разрешение
товарного выпуска. Gate проверяет допустимость в объявленной модели;
промышленная безопасность и экономический эффект не доказаны.

## Быстрый запуск

Нужны Python 3.12 и uv. Команды выполняются из корня проекта:

```sh
uv sync --frozen
LLM_PROVIDER=scripted uv run pytest -q
AGENTIC_DECISION_ENABLED=0 uv run neftecode scenes
AGENTIC_DECISION_ENABLED=0 uv run neftecode serve
```

Открыть http://127.0.0.1:8765/. Расчёт идёт без внешних API. `serve` обслуживает
готовый React-интерфейс из `src/frontend/dist` и поток `/api/stream`.
Условия раскрываются в узле 00 схемы; результат содержит ответ оператору и детали.
`/?mock=review` и `/?mock=agents` открывают дополнительный экран с тремя сценами.

Для показа агентного протокола без языковой модели:

```sh
LLM_PROVIDER=scripted uv run neftecode serve
uv run neftecode agent-demo
```

`scripted` — заранее написанная политика выбора инструментов. Она показывает
механику агентов, но не доказывает работу или пользу LLM.

Зависимости скачиваются при установке. Для полностью закрытой сети нужно заранее
доставить Python и зависимости: одного `uv.lock` недостаточно. Docker-образ и
автономный комплект зависимостей не поставляются. Node.js для обычного запуска
не требуется: сборка frontend входит в Git. [Разработка frontend](src/frontend/README.md).

### Действия в интерфейсе (`neftecode serve`)

- Три сцены (норма, риск, плохие данные) и кнопка «Запустить расчёт»; полная форма — «Расширенные условия».
- «Закрепить для сравнения» фиксирует результат как A; «Что изменится, если…» меняет отказ источника,
  доступность резервуара или производительность и считает B; ниже — парное сравнение с оговорками
  о несопоставимости (срез, модель, provider, горизонт, профиль тяжести).
- «Карта компромиссов» — недоминируемое множество исследованного допустимого пула (выпуск, стоимость, тяжесть).
  Она объясняет варианты и не меняет выбор ядра.
- «Скачать протокол» / «Открыть запись» — JSON с контрольной суммой (не подпись); запись открывается без
  вызова API расчёта и LLM, повтор событий — отдельной кнопкой.

## Данные и артефакты

`task/` и `artifacts/` не хранятся в Git. Наличие исходного `task/` само по себе
не создаёт срезы; чистый клон отличается от полного архива сдачи.

| Комплект | Возможности |
|---|---|
| Чистый клон с зависимостями | Синтетические сценарии, benchmark, agent-demo, интерфейс |
| Дополнительно snapshots, manifest, response_model, source_rules в artifacts | Демонстрация на сохранённых исторических состояниях без исходных CSV/XLSX |
| Дополнительно task и совместимый model.pkl | Исторический advise, построение срезов, исследования |
| Исходные данные и train | Переобучение, отчёты, модель и пороги доверия |

Исходный пакет:

```text
task/
  data/avt_tags.csv
  data/242000_tags.csv
  ЛИМСы ... .xlsx
  Выгрузка ПАК ... .xlsx
  Теги_хакатон.xlsx
  ТЗ_нефтекод.docx
  АВТ_схемы.pdf
  2026-09-16/теги АВТ_24-2000.xlsx
  2026-09-16/формулы_ВАК.xlsx
```

Телеметрия: 189 217 десятиминутных строк, 01.01.2023–07.08.2026,
71 сигнал АВТ и 26 сигналов 24-2000. ЛИМС и ПАК имеют отдельные временные сетки.
Служебные индексы не используются как признаки. Анализы привязываются по времени
и доступности; для ЛИМС принята консервативная задержка публикации 4 часа.

Правила доверия проверяют возраст, пропуски, зависание и расхождение источников.
`train` выводит пороги из обучающего периода. `advise` использует конфигурацию
из `model.pkl`; демонстрация загружает `source_rules.json`, а без него — запасную
конфигурацию. Происхождение правил показывается в результате.
ЛИМС — контрольный факт; неисправный ПАК не считается достоверным.
ВАК исследованы, но ни одна формула не включена как источник качества решения.

Исключённые из данных периоды (остановки/сбои опроса, зависание ПАК, конфликт
ПАК–ЛИМС) задокументированы явно и воспроизводимы одной командой:
[реестр исключённых периодов](docs/excluded-periods.md) /
[машинный артефакт](research/data/excluded-periods.json),
`uv run python scripts/excluded_periods.py --root <каталог с task/>`.
Для класса "плановые остановки установки" в данных нет отдельного флага —
это указано в реестре как честное ограничение, а не домысленный список дат.

## Команды

| Команда после uv run neftecode | Назначение |
|---|---|
| `serve` | React-страница, изменение условий, JSON и поток расчёта |
| `screen --scenario config/scenarios/sour_crude.json` | Сценарное решение и screen.json; без --scenario также используется sour_crude |
| `scenes` | Пять синтетических сцен либо шесть при наличии нужных срезов |
| `benchmark` | Шесть сценариев: hold, пороговое правило, советчик и две абляции |
| `agent-demo` | Четыре сценария scripted-политики; JSON и текст трассы |
| `train` | Обучение и временная проверка прогнозов, отклика и правил доверия |
| `advise --at 2026-01-05T08:00:00` | Решение на исторический момент по исходным данным и модели |
| `snapshot --all` | Срезы из config/snapshot_moments.json |
| `vak` | Проверка формул виртуальных анализаторов |
| `episodes` | Описательная статистика превышений ПАК и предупреждений |
| `tank-check` | Сравнение оценок серы потока/окна с ЛИМС |
| `expert-grid` | Перебор изменяемых условий демонстрации |

`--out` меняет каталог результатов и загружаемых оттуда моделей/срезов.
Для изолированной проверки нужно скопировать необходимые входные артефакты.
`screen --decision <файл>` строит экран из сохранённого решения; это не импорт
SSE-трассы в браузерный replay.

Без срезов `scenes` предупреждает, что реальная сцена риска качества не построена.
На проверенном комплекте аудит 21.09 получил:

| Сцена | Состояние | Ответ ядра |
|---|---|---|
| Нормальный режим | 05.01.2026 08:00 | hold |
| Ухудшение сырья | Синтетическое | hold |
| Зависший ПАК | 20.07.2026 19:10 | hold с резервным источником |
| Устаревшая лаборатория и сломанный ПАК | 16.04.2026 10:10 | refuse |
| Резервуар выведен из работы | Реальный срез с модельным изменением доступности | recommend_scenario |
| Риск ухудшения качества | 24.07.2026 03:00 | recommend_scenario |

Изменение входа не обязательно меняет действие: если текущий режим допустим,
а выгода мала, система может сохранить его.

## Расчёт и агенты

Код разделён на domain, application, infrastructure, evaluation, presentation,
services и composition. Направления зависимостей проверяются AST-тестами.
Основные компоненты — MakeDecision, PlanOperation, GetLiveAdvice, ReplayDecisions.
[Архитектура](docs/architecture.md), [карта кода](docs/code-tour.md).

Планировщик строит постоянные и переходные планы и считает качество, массовый
баланс, выпуск, условную стоимость и тяжесть режима. Gate проверяет серу ≤10 мг/кг,
объявленные свойства продукта, доли компонентов, границы уставок, доступность
компонентов, ограничения запасов и производства. Для основного компонента тот же
расчёт ведёт четыре партии по стадиям `filling → awaiting_passport → ready → draining`,
проверяет вместимость, 12 часов паспортизации, номинальный предел полного слива за
24 часа, массовый баланс и прогноз паспорта наливаемой партии. Неизвестное
обязательное условие не считается выполненным.

Выбор: выпуск → стоимость → тяжесть режима → число изменений → идентификатор.
Политика min_useful_gain удерживает текущий режим при малой экономии.
Можно разрешить небольшую переплату ради меньшей тяжести или числа действий;
в sour_crude окно стоимости составляет 3%. Поиск дискретный, бюджет — 1200,
глобальная оптимальность не заявляется. Провал обязательного возмущения исключает
план; провал диагностического может оставить предупреждение.

OrchestratorAgent, QualityAgent и ReliabilityAgent подключаются поверх ядра.
Специалисты получают ограниченные инструменты и возвращают мнения со ссылками
на результаты; код применяет разрешённые ужесточения и veto. Финальный план
перепроверяется. Если ошибка случилась после принятого ограничения, fallback
сохраняет его и выбирает оставшийся план либо отказывает. Без принятых ограничений
возможен возврат исходного решения ядра. Повторный guard использует ту же модель
и не является независимой физической проверкой.

По умолчанию слой включён с провайдером Z.AI. Явное
`AGENTIC_DECISION_ENABLED=0` в окружении отключает его.
`LLM_PROVIDER=local` использует локальный OpenAI-совместимый endpoint.
Ключи задаются в окружении или локальном .env и не входят в Git.
Живые вызовы могут занимать минуты; temperature=0 не гарантирует повторяемость
выбора внешней модели. Настройки — infrastructure/llm/config.py и config/demo.env.example.

Четыре процесса запускает `uv run neftecode-stack`: data 8766, model 8767,
decision 8768, gateway 8765. Gateway реализует `/api/stream` и передаёт этапы и события
агентов decision-service по мере расчёта; `/api/decide` и `screen` содержат `run_meta` с
версиями модели и кода из считающего процесса. HTTP-протокола отмены у decision-service нет:
кнопка прекращает показ, сервер мог продолжить расчёт. Не запускайте оба сервера на одном порту.
[Контракты сервисов](docs/services.md).

## Результаты и границы доказательств

Прогноз серы — последний пригодный ПАК с медианной поправкой по 20 доступным парам
ЛИМС−ПАК. Метод выбран на пяти rolling-периодах до 2026.
В сохранённом финальном эксперименте 2026 MAE уменьшился 1.802 → 1.616 мг/кг.
Но доля значений выше верхней границы — 6.01% при цели ≤5%, двустороннее
покрытие — 87.1% при цели 90%. Интервал эмпирический, гарантия не заявляется.
Отсутствие будущих данных не доказывает эффект управляющего вмешательства.
[Доказательства прогноза](docs/forecast-evidence.md).

Отклик серы на температуру входа реактора оценивается отдельно по ht.T6.
Выбирается доступная на момент решения оценка из response_model.json.
Live-привязка использует T6/F9/F26, отключает ходы АВТ и не предлагает изменение
расхода ГО с неидентифицированным откликом. Наблюдательный ARX-наклон не доказывает
причинный эффект управления. [Модель отклика](docs/response-model.md).

Блендинг использует свойства конкретной паспортизованной партии; свежий приток меняет
только наливаемую партию и не переписывает качество уже сливаемой. T95 и цетановое
число смешиваются линейно, плотность — по аддитивности объёмов. Обученной модели
цетанового числа нет. Вместимость 5000 м³ и времена 12/24 ч получены из уточнения
организаторов; число резервуаров N=4, плотность, начальные фазы и мощность компонента
глубокой очистки остаются модельными допущениями. Поэтому поставляемые сценарии имеют
`deployment_readiness.ready=false`.

Свежий benchmark 21.09: советчик и пороговое правило дают одинаковые агрегаты —
1500 т допустимого выпуска, 0 нарушений выданных планов и 1 отказ в шести сценариях.
На спокойных сценариях правило дешевле: 1.05 против 1.086 усл.ед./т, а советчик
избегает изменений при экономии ниже сценарного порога 5%. У hold 46 проваленных
проверок — это не число аварий или партий брака. Отключение переходных планов
и конечного резерва не меняет выпуск на этом наборе.

[Сохранённый стресс-тест](research/results/independent-evaluation-2026-09-20.json) использовал
бюджет **400**: советчик проходил slow_weak_response, а простое правило — нет.
Повтор 21.09 с рабочим бюджетом **1200** выбирает c0030 вместо c0036: обе стратегии
получают по 7 нарушений в slow_weak_response и nonideal_mixing.
Преимущество старого эксперимента нельзя переносить на текущую конфигурацию.
Среды меняют параметры того же симулятора; структурно независимой модели нет.

`agent-demo` подтверждает работу протокола и изменение выбора.
[Same-input исследование](research/results/agent-value-evaluation-2026-09-20.json) сделано
со scripted-провайдером и бюджетом 400. Оно не доказывает пользу LLM; раннер сравнения
не гарантирует одинаковое подключение robustness у ядра и внешнего agentic_runner.
Исторические live-трассы подтверждают вызовы инструментов, но не статистическое
преимущество и не повторяемость текущего live-провайдера.

## Соответствие ТЗ и ограничения

Основной цикл, отказ, несколько вариантов, Gate, журнал и временная проверка
прогноза реализованы. [Трассировка требований](docs/requirements-map.md).

ВАК не подключены как резервный источник из-за неподтверждённого качества и
привязки показателей. ВСГ/сырьё и давление не управляются; ТЗ разрешает ограниченный
обоснованный набор воздействий и не требует каждое из перечисленных воздействий.
Карта показывает недоминируемые варианты исследованного допустимого пула;
итоговое решение по-прежнему определяется политикой ядра, а не кликом на карте. Надёжность — прокси-тяжесть, не модель ресурса или вероятности отказа.

Партийная модель парка реализует уточнения о 5000 м³, 12 часах паспортизации и
номинальном 24-часовом сливе. Фактические уровни и стадии в live-данных не переданы:
система проверяет одни и те же планы на всём интервале τ от нуля до времени налива
и выбирает из общего допустимого пула. Непрерывная проверка использует нижние границы
запаса готовых партий и свободных ёмкостей, верхнюю границу серы, включая обязательные
стрессы. Три прямых прогона оставлены как диагностика. Если общий план среди
рассмотренных не подтверждён, рекомендация не выдаётся.
Ответ показывает изменение выпуска и условной стоимости относительно выбора при
исходной модельной фазе. Проверка покрывает все τ периодического расписания модели
на временной сетке горизонта 3 ч; реальное расписание парка неизвестно. Достаточные
условия требуют горизонта короче налива и паспортизации, одинаковых начальных свойств
партий и отсутствия индивидуальной замены начального запаса. Неподтверждённый план
не обязательно физически невозможен. На срезе риска 24.07.2026 общий план даёт
50 т/ч (150 т за 3 ч) вместо номинальных 100 т/ч; норма сохраняет режим.
Сквозная отмена удалённого расчёта через HTTP-стек не реализована как протокол и не заявляется.

## Поставка

```sh
bash scripts/package.sh
```

Скрипт копирует отслеживаемые файлы из явного списка каталогов поставки
(`scripts/submission_files.py`) и перечисленные артефакты; проверяет
обязательные файлы, непустые срезы, отсутствие task, кэшей, .env и похожих на секреты
записей. Модель и отчёты нужно подготовить заранее: скрипт не обучает их и не
запускает pytest. Новые документы необходимо добавить в Git перед упаковкой.
Отправка не выполняется.

Для advise нужны исходные данные, для подготовленных сцен — сохранённые срезы.
Остановка сервисного стека использует POSIX; ограничение Windows отмечено skipif.
Результаты локальных проверок не экстраполируются на другие платформы.
