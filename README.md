# Нефтекод

Первый рабочий проход советчика: реальные данные → прогноз серы → проверка данных →
агенты качества и оборудования → подбор смешения → рекомендация либо отказ с журналом.
Это исследовательский прототип, а не готовая система управления заводом.

## Запуск

Python 3.12 и `uv`. Выполнять из корня репозитория:

```sh
uv sync --frozen
uv run neftecode train
uv run neftecode advise --at 2026-01-05T08:00:00
uv run pytest -q
```

Обучение читает исходники из `task/`, не изменяя их. Первый запуск требует скачать зависимости;
расчеты далее локальные. Внешние API и ключи не нужны. `uv.lock` фиксирует версии.

Результаты в `artifacts/`:

- `report.md` — читаемые результаты проверки и сценарии.
- `metrics.json` — ошибки, обнаруженные превышения, ложные тревоги, покрытие диапазонов.
- `risk_metrics.json` и `risk_predictions.csv` — отдельное обнаружение превышений и сравнение при заданном бюджете ложных тревог.
- `predictions.csv` — прогнозы на тестовом периоде и факты для последующей оценки.
- `replay.csv` — решения во всех тестовых моментах.
- `audit.jsonl` и `demo.json` — полные входы и ход расчета для показательных сценариев.
- `model.pkl` — обученные модели, параметры и калибровка. Загружать только собственные локальные артефакты.
- `manifest.json` — хеши исходников, кода, зависимостей и параметры запуска.

`uv run neftecode demo` повторяет сценарии без обучения. Без результатов обучения доступны
четыре синтетических сценария. `--out PATH` задает каталог результатов.

`advise --at ...` запускает обученные модели на выбранный момент, заново собирая доступные
тогда измерения, и сохраняет `decision-YYYYMMDD-HHMMSS.json`. Для текущей калибровки доступны
моменты начиная с 2026-01-01. Более ранний запуск запрещен: модель знает результаты из его
будущего. При запросе за пределами свежих данных будет мотивированный отказ.

## Как устроено

`data.py` читает отдельно временные оси ЛИМС и ПАК, различает теги АВТ и гидроочистки,
строит текущие значения, средние и изменения за прошлые 6 часов. Отложенные анализы
доступны только после заданной задержки. Будущие значения не подставляются.

`forecast.py` сравнивает последний доступный ЛИМС, проверенный ПАК, линейную модель и
две модели CatBoost: с ПАК и без него. Цель — лабораторная сера после гидроочистки за 2 часа
до взятия каждой пробы. Один реальный анализ — одна строка оценки.
ЛИМС является эталоном обучения/проверки; использование ПАК для прогноза не меняет приоритет эталона.

Обучение: 2023–2024. Выбор по средней ошибке на общих анализах: первое полугодие 2025.
Калибровка диапазона: второе полугодие 2025. Тест: 2026. Неизвестные на границах периодов
результаты исключаются. Тест не подбирает модель, параметры или диапазон.
Сравнение на общем подмножестве приведено отдельно от оценки доступности каждого метода.

`risk.py` отдельно ищет превышение предела: два простых порога, логистическая модель и
CatBoost с ПАК/без ПАК. Выбор — на общем validation при экспериментальном бюджете 20%
ложных тревог среди проб без превышения. Затем порог заново устанавливается на calibration
и замораживается. Этот бюджет не гарантирован в новом режиме. Score модели не называется
вероятностью; дополнительная тревога не отменяет жестких проверок смешения.
Резерв при отказе ПАК выбирается отдельно среди методов без него.

Период 2026 уже просмотрен в первом эксперименте. Новые сравнения на нем — фиксированный
исторический ориентир, не новый слепой тест. Первый результат сохранен в
`context/experiments/baseline-v1.json`.

`agents.py` содержит пять ролей. Агент данных проверяет доступность источников, зависание
и расхождение ПАК с анализом той же пробы. При отказе ПАК используется отдельная модель без его
признаков. Агент качества проверяет верхнюю оценку серы, агент оборудования — ограничения
сценарного насоса. Координатор возвращает запреты оптимизатору; тот повторяет поиск с меньшим
выпуском. Допустимые варианты сравниваются по выпуску, условной стоимости, энергии и нагрузке.
Приоритет после жестких проверок: выпуск, затем стоимость. Допустимый текущий режим сохраняется.
Поиск дискретный, с шагом доли 5 п.п. и выпуска 10 т/ч; глобальный оптимум не заявляется.

## Что реально и что задано для демонстрации

Телеметрия, целевые анализы и результаты теста реальные. Все условия смешения,
резервный компонент, ограничения насоса и стоимость заданы в `config/blending-demo.json`.
Для массовых долей сера считается материальным балансом. Даже допустимый сценарный результат
не разрешает выпуск товарного топлива: другие необходимые свойства не проверены.

Горизонт прогноза, задержка ЛИМС, пороги свежести и подозрения на отказ ПАК — экспериментальные
допущения в `config/experiment.json` и коде проверок. Требуется технологическое подтверждение.
Датчик, постоянный в течение часа, только подозревается в зависании; 307 и отрицательные значения
телеметрии не удаляются автоматически. Сомнительные формулы ВАК пока не используются.

Карта физических управляющих тегов еще не подтверждена. Модель прогноза не считается моделью
эффекта управления. Прототип пока не предлагает менять режимы АВТ или гидроочистки.
Воспроизведение истории показывает работу алгоритма, не измеренную экономию от его действий.
Резервная модель проверена на обычной истории без признаков ПАК, но не на реальных размеченных отказах.
Полные критерии качества, промышленная надежность и управление всей цепочкой остаются следующими этапами.

Рабочий контекст и приоритеты — в `context/state.md` и `context/implementation-strategy.md`.
