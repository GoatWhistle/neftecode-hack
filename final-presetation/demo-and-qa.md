# Что показать и как отвечать

## Три подготовленные сцены

Проверено локально 26.09.2026 на `main b52027f`, `LLM_PROVIDER=scripted`, `AGENTIC_DECISION_ENABLED=1`. [Сводка результатов и границ проверки](evidence.md).

| Сцена | Контрольный вход | Что крупно показать |
|---|---|---|
| Риск | `sour_crude`, `20260724-030000`, `healthy` | `c0001`: 100 → 50 т/ч, 150 т за 3 ч, почему исходный план исключён; проверка общей фазы, цена по выпуску; `commercial_release_allowed=false` |
| Норма | `baseline`, `20260105-080000`, `healthy` | Сохранить режим, 300 т за 3 ч; вмешательство не требуется |
| Плохие данные | `baseline`, `20260416-101000`, `both_broken` | Отказ по данным, без плана; какие измерения нужны. Не показывать нули вместо недоступных показателей |

В риск-сцене открыть **короткий фрагмент трассы**: оркестратор → инструмент качества/надёжности → вердикт → финальная проверка. Подписать `scripted`; в сохранённом прогоне агенты приняли план ядра, `constraints_applied=[]`. Доли выбранной смеси: основной компонент 100%, глубокая очистка 0%; это объясняется уже готовой партией. Не говорить, что 150 т — исторический фактический выпуск.

Подготовить состояние каждой сцены заранее. Проверить, что карточка и дата совпадают; в запасе иметь статичные кадры реального прогона или запись с честной маркировкой. Репетиция UI пока не подтверждена.

Для самостоятельной проверки из корня репозитория после установки зависимостей:

```sh
LLM_PROVIDER=scripted AGENTIC_DECISION_ENABLED=1 uv run neftecode serve --port 18826
```

Открыть `http://127.0.0.1:18826/` и выбрать даты трёх сцен. Контрольные адреса API для проверки ответа, не для показа жюри:

```text
/api/decide?scenario=baseline&snapshot=20260105-080000&fault=healthy
/api/decide?scenario=sour_crude&snapshot=20260724-030000&fault=healthy
/api/decide?scenario=baseline&snapshot=20260416-101000&fault=both_broken
```

## Ответы на наиболее опасные вопросы

**«Если агенты не изменили план, зачем они?»** В этом scripted-прогоне они проверили план ядра и оставили его. Отдельные роли дают проверяемые оценки качества и надёжности, записанные в трассу. Прирост качества решения от живой LLM здесь не доказан; сравнение с детерминированным ядром — следующая проверка.

**«Почему не хватит порога по сере?»** Порог может сигнализировать о риске, но не рассчитывает сам по себе доступность партий, задержки и выбор допустимого действия. Наш продукт связывает эти шаги. При этом устойчивое превосходство по выпуску/стоимости над простым правилом пока не доказано.

**«Почему прогноз такой простой?»** Выбор делали по временной проверке, а не по сложности. На одинаковых 233 пробах финального периода MAE улучшилась с 1.802 до 1.616 мг/кг относительно последнего ПАК. Недопокрытие интервала 6.01% выше целевых 5%, поэтому неопределённость не скрываем.

**«Вы гарантируете качество при любой фазе?»** Нет. Проверяем любой общий сдвиг **заданного периодического расписания** на горизонте три часа при условиях модели. Произвольные независимые фазы четырёх резервуаров и неизвестные реальные паспорта этим не покрыты.

**«Сколько экономии и насколько снизится аварийность?»** Заводскую экономию и аварийность не измеряли. Стоимость — условный показатель модели, тяжесть режима — индекс, не вероятность отказа. Для практической оценки нужны цены, данные оборудования и наблюдательный пилот.

**«Это промышленная рекомендация?»** Нет. Во всех проверенных сценах `commercial_release_allowed=false`. До пилота нужны реальные уровни и паспорта партий, согласованные уставки, подтверждение отклика и сравнение с текущей практикой.

**«Работает без интернета и при отказе LLM?»** Детерминированное ядро и scripted-политика работают локально после установки зависимостей. Live-провайдер здесь не проверялся. Ошибка агентного слоя должна быть явно помечена; принятые ограничения не должны исчезать молча.

**«Модель прогноза доказывает, что выбранная смесь кондиционная?»** Нет. MAE измерена для серы потока после гидроочистки. Допустимость смеси проверяется отдельной сценарной моделью с её допущениями; реальные свойства партии требуют паспорта.

**«Прогноз серы потока 14.93 мг/кг выше лимита 10. Почему план допускается?»** Это разные объекты. 14.93 мг/кг — прогноз нового притока; в продукт на данном коротком горизонте уходит уже готовая партия. Её расчётное качество проверяется отдельно. Новый поток наполняет другую партию и проходит цикл паспортизации.

**«Какие параметры парка фактические?»** Из ответа организаторов даны 5000 м³ на резервуар, паспорт 12 часов и номинальный полный слив 24 часа. Четыре резервуара, фазы и часть начальных условий заданы сценарием; реальные уровни и паспорта неизвестны.

**«Вся цепочка АВТ — ГО — смешение действительно управляется?»** Цепочка связана в сценарной модели. На историческом входе неподтверждённые воздействия АВТ блокируются: тег нельзя менять как уставку без подтверждённой карты. Полноту промышленной привязки не заявляем.

**«Ваша карта Парето даёт глобальный оптимум?»** Нет. Это недоминируемые альтернативы внутри ограниченного исследованного пула; финальный вариант выбирает заданное правило. Глобальная оптимальность и полный набор стресс-проверок всех альтернатив не доказаны.

**«Доказан ли эффект изменения температуры?»** Историческая модель показывает связь в пределах наблюдённых режимов, но работа регуляторов и совместное изменение параметров не позволяют назвать её причинным эффектом нового вмешательства. Для него нужна отдельная проверка на установке.

**«Где энергопотребление?»** В текущем сценарии есть условная стоимость и индекс тяжести режима, но прямого измерения или доказанного прогноза энергопотребления для каждого действия нет. Этот критерий нельзя объявлять закрытым количественно; для пилота нужны соответствующие измерения и тарифы.
