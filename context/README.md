# Рабочий контекст

## Правила пользователя

- Отвечать по-русски, кратко, четко и понятно.
- Без воды, сложных терминов и огромных ответов.
- Хранить рабочий контекст в файлах папки `context/`.
- Работать в ветке `main`. Push и отправка организаторам — только по отдельному поручению.
- Для независимых проверок использовать субагентов средней мощности, предпочтительно GPT-5.6 Luna.
- По запросу архитектуры давать техническое описание с четкой структурой; различать целевое решение и реально реализованный прототип.
- Не сохранять пароли, токены и другие секреты.
- Не выдавать идею за реализованную функцию, модельный результат за эффект на заводе, корреляцию за доказательство причинности. При противоречиях явно отмечать источник и дату.

## Хранение

Порядок входа после перерыва: этот файл → `state.md` → `solution.md` → `architecture.md`.

- `state.md` — текущее состояние, последние решения и открытые ограничения.
- `solution.md` — основной документ: полная идея решения, границы, приоритеты, демонстрация и проверка.
- `architecture.md` — целевая архитектура, контракты, цикл агентов и статус реализации компонентов.
- `services.md` — фактические границы четырёх процессов, HTTP-контракты и команды запуска.
- `requirements-map.md` — трассировка требований ТЗ, карта управляющих переменных и открытые вопросы. Машиночитаемая часть — `config/parameters.json`.
- `code-tour.md` — карта кода.
- `data-flow.html` — страница пути данных: от источников до решения.
- `defence.md` — материалы защиты: решение, архитектура, сквозной сценарий, сравнение, честные ограничения, ответы на ожидаемые вопросы.
- `benchmark-audit-2026-09-19.json` — зафиксированные хеши сценариев и агрегаты бенчмарка; используется тестом `tests/evaluation/test_benchmark.py`, не удалять.
- `task-review/` — исходное ТЗ и разбор данных.
- `experiments/`, `interval-check/`, `forecast-research/`, `response-research/` — сырые данные и скрипты исследований, на которые ссылаются `README.md` (корень) и `RESPONSE_MODEL_FINAL.md`/`RESPONSE_MODEL_T6.md`.
- Историческая переписка по задачам, разборы сессий вопросов и промежуточные аналитические записки удалены 2026-09-20 как устаревший журнал работы; текущее состояние — только в `state.md`.
- Поддерживать контекст актуальным, чтобы продолжать работу после перерыва.
