## Что работает

Советчик оператору АВТ → гидроочистка → смешение: доступные данные → проверка доверия → прогноз →
постоянные/переходные планы → модель последствий и запасов → обязательные проверки (Gate) → сравнение →
объяснение. Поверх детерминированного контура — слой LLM-агентов (`OrchestratorAgent`, `QualityAgent`,
`ReliabilityAgent`): выбирают инструменты и предлагают ужесточающие ограничения; числа, допустимость,
ранжирование, финальная перепроверка и устойчивость — тот же детерминированный код, любой сбой LLM —
детерминированное решение без изменений. Четыре HTTP-процесса (data, model, decision, gateway) — общее
ядро; запуск — `neftecode-stack`. CLI: `train`, `advise`, `snapshot`, `screen`, `scenes`, `serve`,
`benchmark`, `agent-demo` и др. — `neftecode --help`.

Backend: **1316 тестов проходят** (последний прогон 2026-09-20, полный набор, дважды подряд).
Frontend: `npm run build` (tsc + vite) — без ошибок.

## Явные границы — не готово к промышленному внедрению

Это не забытые пробелы, а объявленные условия — код сам их проверяет и показывает в каждом решении:

- **`deployment_readiness.ready = false`.** Завод не передал фактический рабочий объём и полезную
  вместимость резервуарного парка и допустимую мощность наработки ДТ более глубокой очистки. Пока это
  не получено — числа парка (4000 т и т.п.) остаются только сценарными.
- **`commercial_release_allowed = false`** всегда, по конструкции. Советчик не разрешает товарный выпуск.
- **Прогноз серы после ГО**: цель `exceed_upper` ≤5% на честном слепом тесте 2026 года **не достигнута**
  (фактически 6.01%). Улучшение MAE (1.802 → 1.616 мг/кг) подтверждено, целевой порог — нет; это не
  подгонялось задним числом.
- **Польза управления, ресурс оборудования и промышленная безопасность прямо не доказаны** — отдельно
  зафиксировано по итогам Q&A с организаторами; это дополнительная метрика/диагностика, не доказательство.
- **Смещение ПАК–ЛИМС в оценке серы резервуара** — исследовано, само по себе непостоянно (медиана по
  полугодиям от −0.97 до +1.04), варианты учёта предложены, но не внедрены — ждёт отдельного решения.
- Ряд пунктов ТЗ сознательно не реализован с объяснением почему (не пропущен): ВАК не служит источником
  качества (формулы проверены и как измерение непригодны), соотношение ВСГ/сырьё не моделируется как
  управляющая переменная (нет подтверждённых границ и отклика), давления АВТ/ГО — не управляемые
  воздействия, Парето-фронт по нескольким целям не строится (завод не задал веса). Подробности и
  обоснования — `README.md` (корень, раздел ограничений) и `requirements-map.md`.

## Последние изменения (2026-09-19 — 2026-09-20)

1. **Баг explain-слоя**: `refusal.kind == "agent_rejected"` (допустимый план был, но агенты качества/
   надёжности его отклонили) молча схлопывался в `no_feasible_plan` — экран лгал «допустимых вариантов
   ноль», хотя Gate реально находил допустимые кандидаты. Исправлено в `explain_types.py`, `refusal.py`,
   `risk_block.py`, фронт (`ChoiceStage`, `GateStage`, `Refusal.tsx`). Слито с параллельным чужим коммитом
   (`mikhailkhorokhorin`, рефакторинг фронта) через `git merge`, конфликт был только в собранном
   `dist/assets/index.js`, решён пересборкой.
2. **Ускорение агентного слоя**: независимые tool-вызовы одного ответа LLM (в первую очередь
   `ask_quality_agent`/`ask_reliability_agent`, которые оркестратор реально просит в одном шаге)
   выполняются параллельно (`ThreadPoolExecutor` в `agentic/loop.py`), кроме `search_candidates`
   (мутирует session) и `finalize`/`submit_opinion`. Добавлены блокировки для общего состояния
   (`AgentBudget`, `DecisionSession.veto`, `AgentTrace.add`); прогресс-события явно прокинуты в рабочие
   потоки. Измеренное ускорение — **×1.6–2×** (не ×4: глубина диалога оркестратора с LLM, 2–5
   последовательных раундов, принципиально не параллелится без смены протокола).
3. **Найден и исправлен недетерминизм вердикта**: `LLM_TEMPERATURE=0.2` по умолчанию давал на одном и том
   же пограничном входе (запас по сере 0.39 против операционных 1.0) то `confirmed_legacy`, то `refused`.
   Дефолт изменён на `temperature=0` (`infrastructure/llm/config.py`) — два контрольных прогона подряд
   дали идентичный вердикт и время (разброс 0.5% вместо ~33%).
4. **Широкая проверка обеих правок**: все 6 синтетических сценариев (`ample_reserve`, `baseline`,
   `light_component`, `no_feasible`, `sour_crude`, `winter_grade`) — без падений, `invalid_final: 0`
   везде (нет признаков вырождения ответов от `temperature=0`); реальный исторический момент
   (`advise --at 2026-05-07T10:10:00`, тот самый со специалистами) — 105.7с против исторических ≈212с,
   тот же вердикт; прод-путь через реальный HTTP-стек (`neftecode-stack` → `gateway`/`decision_service`,
   `/api/decide`) — 99.7с, без ошибок, кэш гейтвея подтверждён (повтор 0.013с, тот же `decision_id`).
5. **Чистка репозитория (2026-09-20)**: удалены ~40 файлов рабочего журнала (`context/backlog.md`,
   `tasks-*.md`, `qa-session-*.md`, разовые аналитические записки, `plan/00–08`, корневые `TODO.md`/
   `FRONTEND_TODO.md`, `context/history/`) — история задач и промежуточных обсуждений, не описание
   решения. Мёртвые ссылки на них вычищены из оставшихся документов (`README.md`, `architecture.md`,
   `solution.md`, `defence.md`, `requirements-map.md`, `data-flow.html`) и из строки кода
   (`infrastructure/data/quality.py`). `context/benchmark-audit-2026-09-19.json` по ошибке попал под
   удаление и восстановлен — на него ссылается `tests/evaluation/test_benchmark.py`.
