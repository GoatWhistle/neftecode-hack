# U3: тяжесть режима до и после (22.09.2026)

Причина дефекта: `Economics.severity` брала опору и масштаб из `stage.model.reference_*` и диапазона уставок.
В live-привязке эти же поля перезаписываются: `reference_temp/flow` = текущий режим (нужны линеаризации отклика
качества), `min=max=current`. Индекс текущего режима был 0 по построению, масштаб вырождался в 1e-9.

Исправление: отдельный профиль `policy.severity_profile` (`severity-profile/1`, источник `scenario_proxy`):
опора и масштаб температуры/расхода берутся из исходных сценарных параметров до привязки измерений
(T 348 °C, масштаб 27 °C; расход 256 м³/ч, масштаб 44 м³/ч; веса 0.7/0.3 — прежние сценарные). Линеаризация отклика
(`reference_temp_c`, `reference_space_velocity_m3h` в модели) не менялась. Для сценариев без live вычисление совпадает с прежним.
Границы отдельно: паспортный предел (не задан), историческая область модели отклика (T6, диапазон исследования), сценарный предел.

| Сцена (scripted, live-привязка) | До: статус / план / тяжесть | После: статус / план / тяжесть |
|---|---|---|
| Норма (baseline, 05.01) | hold / hold / 0.0 | hold / hold / 0.514 (T6 367.8 °C, вклад температуры 0.514) |
| Риск (sour_crude, 24.07) | recommend / c0042 / 0.0 | recommend / c0042 / 0.535 (T 0.392 + расход 0.142; сценарный предел 0.75, запас 0.215) |
| Плохие данные | refuse / — / — | refuse / — / — (текущий режим по сценарным уставкам, происхождение указано) |

Выбор плана и стоимость не изменились: температура в live заморожена, кандидаты различаются рецептом/расходом
сырья, вклад тяжести одинаков. Порог `max_severity_index=0.75` остался на той же шкале (сценарной), не перенесён на другую.
Агентные ограничения по тяжести отсутствуют (агенты видят только `severity_index` в карточках), пороги агентов не менялись.
Нулевой индекс нормы — по определению только при T ≤ опоры; live-норма 05.01 стоит на T6=367.8 > 348, поэтому 0.514.
