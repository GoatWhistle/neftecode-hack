      слив 24 ч», налив нового начинается каждые C/q часов. Схема замыкается, если
      (N − 1)·C/q ≥ 36 ч, то есть q ≤ (N − 1)·C/36: при N = 3 — до 232.3 т/ч, при N = 4 —

- [x] Стадия парка на момент среза неизвестна — перебор по стадиям.
      Стадия задаётся одним числом τ — временем с начала налива текущего резервуара (0…C/q);
      стадии остальных следуют из расписания. Проверяются как минимум τ ≈ 0, C/2q и C/q − 0.5 ч.
      Совет выдаётся, если план допустим при всех проверенных τ; иначе — отказ с причиной
      «совет зависит от стадии резервуаров, нужен уровень» и перечнем τ, где план не проходит.
      Механизм аналогичен существующему `tank_estimate` (риск `tank_estimate_sensitive`).
      Качество партий берётся из данных: сера наливаемой партии — среднее доверенных показаний

      в прошлом. Долю отказов из-за неизвестной стадии показать в T9; если она велика, это
      результат (заводу нужен тег уровня), а не повод ослабить проверку.
- [x] Слив и выпуск: слив одного резервуара = C / 24 ч ≈ 174.2 т/ч, статус derived из ответа 21.09.

## Как работать с субагентами

Типы:
- `Explore` / `caveman:cavecrew-investigator` — найти код, вернуть `file:line`;
- `general-purpose` — реализация задачи;
- `caveman:cavecrew-reviewer` — ревью диффа;
- `Plan` — дизайн для T2 и E2.

Изоляция: задачи, которые идут параллельно и трогают код, запускай с `isolation: "worktree"`.
Сливай в `main` сам, по одной, с прогоном тестов после каждого слияния, затем коммит задачи.

Промпт субагента обязан содержать: ID задачи; формулировку и критерий готовности из
`task-pool.md`; файлы; жёсткие правила 1–4 и 6; запрет трогать `src/frontend/`; запрет коммитить;
что вернуть — дифф, вывод тестов, как проверен критерий.

Ты проверяешь каждый результат сам: прогоняешь тесты, сверяешь критерий. Непроверенный результат
не закрыт. После каждой задачи, где менялась логика, запусти `caveman:cavecrew-reviewer` на дифф
до коммита.

Что можно параллельно:

- Этап 1: I2 ∥ I4; I1 после Z5; I3 после I2.
