# Перенос на Clean Architecture и DDD

Дата начала: 2026-09-13. Работа выполняется в `main` отдельными коммитами.

## Цель

```text
presentation ─┐
infrastructure ├→ application → domain
evaluation ───┘
```

- `domain` содержит бизнес-сущности и правила, не читает файлы и не знает про ML, HTTP и CLI.
- `application` содержит сценарии `MakeDecision`, `PlanOperation`, `GetLiveAdvice`, `ReplayDecisions` и порты.
- `infrastructure` реализует чтение CSV/XLSX/JSON, ML и сохранение артефактов.
- `evaluation` содержит benchmark, ВАК, эпизоды и проверки устойчивости.
- `presentation` содержит CLI, HTTP и HTML.

## Предметные контексты

- `shared`: общие статусы, ошибки, единицы и происхождение значений.
- `monitoring`: наблюдения, состояние установки, прогнозы и доверие к данным.
- `production`: сценарий, режим, свойства потоков, смешение, запасы и экономика.
- `advisory`: планы, траектории, обязательные проверки и итоговое решение.

## Неподвижные контракты

- Команды CLI и их смысл не меняются.
- JSON решения сохраняет текущие поля и значения.
- Результаты четырёх сценариев не меняются.
- Replay и pause/resume воспроизводят прежний результат.
- Старые плоские импорты после завершения удаляются, совместимые обёртки не остаются.

## Этапы

1. Зафиксировать поведение и правила зависимостей.
2. Выделить доменные контексты и объединить дублирующиеся типы.
3. Ввести прикладные сценарии и порты.
4. Вынести инфраструктурные адаптеры.
5. Вынести CLI, HTTP и HTML.
6. Вынести оценку и эксперименты.
7. Удалить плоские модули, обновить документацию, fingerprint и комплект сдачи.

После каждого этапа запускаются все тесты и отдельный аудит Luna medium. После изменения путей
моделей fingerprint считается рекурсивно, модели переобучаются, итоговый архив проверяется в
чистом окружении.
