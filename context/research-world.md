## Научные работы

### 1. ProcessAgent — первый кандидат для подробного разбора

[Статья, 2025](https://arxiv.org/html/2506.20921v2), [репозиторий авторов](https://github.com/tongzeng24/ProcessAgent).

Пять ролей: получение контекста и диапазонов, начальные параметры, проверка, симуляция, предложение следующего режима. Расчеты делает IDAES/Pyomo, взаимодействие построено на AutoGen. Эксперимент — установившийся процесс превращения толуола в бензол, четыре изменяемых параметра. Это не дизель и не управление меняющимся производством.

Авторы сообщают об ускорении примерно в 31 раз относительно перебора 10 000 комбинаций. Это не доказательство ускорения относительно всех оптимизаторов: IPOPT дал лучшие значения затрат и отношения выхода к затратам в показанном сравнении. Число шагов разных алгоритмов также не равно времени выполнения.

В репозитории действительно есть Python-код, расчетная модель, настройки и сохраненные результаты. Проверены дерево файлов и отдельные места исходников. Готовность запуска не проверена. Лицензия в дереве не обнаружена, GitHub API возвращает `license: null`; не считать свободное копирование подтвержденным. В `main.py` встречается `eval` для обработки сообщения — реализацию нельзя переносить без проверки обработки данных.

Берем идею цикла «предложение → проверка → расчет → улучшение». Обязательные ограничения нашего кейса задаем из ТЗ и модели, а не из догадок LLM.

### 2. From Text to Simulation — построение модели по описанию

[Статья, январь 2026](https://arxiv.org/html/2601.06776v1).

Четыре агента разбирают задачу, строят схему соединений, задают параметры и оценивают расчет. Используется поиск по вариантам. Близко к автоматизации подготовки симулятора, но отличается от выбора режимов уже заданного производства. Проверены описание метода и страницы статьи; собственный исполняемый репозиторий в этом поиске не подтвержден.

### 3. CRAFTS — полезная архитектура, пока без доступного рабочего комплекта

[Статья, 2 августа 2026](https://arxiv.org/abs/2608.01369), [репозиторий](https://github.com/Galigeigei-Z/CRAFTS-Multi-agent-for-Equation-oriented-PSE).

Семь ролей строят модели IDAES/Pyomo, промежуточные структуры проверяются программными правилами. Авторы заявляют набор OpenIDAES-450. Однако README прямо сообщает о предварительном описании: данных, весов и материалов оценки пока нет. Через GitHub API проверено: четыре файла, исполняемых Python-файлов нет. Берем принцип проверяемых промежуточных результатов; запускать готовый CRAFTS сейчас не на чем.

### 4. Более ранние и соседние подходы

- [Agent-based refinery supply chain, 2009](https://www.sciencedirect.com/science/article/pii/S1570794609707400): решение нештатных ситуаций через агентную модель и сравнение симуляций. Исследовательский аналог поддержки решений; проверено описание, не воспроизводилось.
- [Обучение для смешения бензина, 2023](https://arxiv.org/abs/2309.02929): полезный соседний процесс для понимания оптимизации рецептуры; нельзя переносить свойства бензина на дизель.
- [Гидроочистка и перегонка с моделями на данных](https://psecommunity.org/LAPSE%3A2023.1471): несколько целей и учет неопределенности прогноза. Полезная идея — не выбирать режим только потому, что он выглядит выгодным в плохо изученной области.
- [Multi-agent RL для перегонки нефти](https://www.sciencedirect.com/science/article/pii/S0009250926012352): найдена публикация о согласовании нескольких целей. Пока проверено только описание из поиска; полный текст, дата выпуска и код не подтверждены. Не опираемся на численные результаты.

## Наш выбор после обзора

Статус обновлен по замечанию пользователя: технические шаги ниже отложены. Текущий приоритет — чтение и понимание кейса до выдачи полного ТЗ.

1. Разобрать ProcessAgent как образец взаимодействия с расчетной моделью.
2. Проверить минимальный пример IDAES и простой процесс PC-Gym; выбрать стенд по времени подключения и пригодности модели.
3. Вынести модель за единый программный интерфейс, чтобы заменить ее после 8 сентября.
4. Подготовить сравнение простых правил, единого оптимизатора и агентов на одинаковых сценариях.
5. Не начинать с обучения собственной большой модели, детального моделирования всего НПЗ или множества сервисов.

Минимум предметных знаний и проектные требования — в `engineering-basics.md`.
