## Продуктовая ставка

Оператор видит риск заранее, сравнивает допустимые действия и понимает причину выбора.
Для жюри показываем воспроизводимый эпизод: проблема в качестве → вариант оптимизатора →
запрет оборудования → пересчет → обоснованное решение. Каждый вывод имеет численный след.

## Что уже сделано

Локальный пакет Python с фиксированными зависимостями. Команда `uv run neftecode train`
проходит исходные данные, обучение, временную оценку, сценарное смешение и журнал агентов.
Результаты: `artifacts/report.md`, `metrics.json`, `predictions.csv`, `replay.csv`, `audit.jsonl`.
Повторить демо без обучения: `uv run neftecode demo`.
Запрос к обученному советчику на произвольный момент: `uv run neftecode advise --at 2026-01-05T08:00:00`.
Срез источников собирается заново; ранняя дата до готовности калибровки запрещена.

- 189 217 строк телеметрии; 1458 целевых анализов внутри покрытия и с достаточной историей.
- 296 признаков: оба участка, прошлые окна, доступные анализы и их возраст.
- Train 792 анализа (2023–2024), validation 193 (2025 H1), calibration 224 (2025 H2), test 249 (2026).
- Пять методов: последний ЛИМС, проверенный ПАК, Ridge, CatBoost, CatBoost без ПАК.
- Выбор на общем validation — последний ПАК: MAE 1.3213; CatBoost без ПАК очень близок, 1.3236.
  Значимость такой разницы не установлена. Выбор автоматически следует заданному правилу.
- На тесте средняя ошибка CatBoost без ПАК 1.56 мг/кг (249 анализов), ПАК 1.76 (229 анализов).
  Из-за разной доступности отдельно считается ошибка на общем подмножестве.
- Существенная проблема: оба CatBoost почти постоянно прогнозируют ниже 10; найдено 0 из 36
  превышений точечным прогнозом. Низкая MAE не решает основную задачу контроля риска.
- Диапазоны с целью 90% на тесте покрывают примерно 80% для резервного CatBoost и 88% для ПАК.
  Верхние границы находят больше превышений, но дают много ложных тревог. Это исследовательская
  основа, не готовый надежный прогноз.
- На 249 тестовых моментах сценарный советчик: 170 вариантов изменения, 66 сохранений режима,
  13 отказов. Эти числа характеризуют модельный сценарий, не эффект или безопасность завода.

Пять ролей реализованы классами в одном приложении. Есть отдельная проверка зависания ПАК,
сопоставление с ЛИМС той же пробы, резервный прогноз без признаков ПАК, обязательные ограничения,
пересчет после запрета оборудования, альтернативы и стабильный идентификатор решения.

Пример взаимодействия: верхняя сера 14; исходные 100 т/ч; резерв 1–3 мг/кг;
насос максимум 30 т/ч. Первый поиск получает запрет. После пересчета: 70 т/ч,
40% резерва, верхняя сера смеси 9.6, насос 28 т/ч. Все условия примера синтетические.

## Следующие три приоритета

1. **Повысить качество обнаружения риска.** Первый отдельный классификатор уже проверен (ниже);
   устойчивого преимущества не показал. Дальше исследовать режимы, стоимость пропуска
   и ложной тревоги, неоднородность режимов, задержки и адаптацию диапазона. Проверять на нескольких
   временных окнах, сравнивать с переносом измерения. Не оптимизировать только среднюю ошибку.
   Текущий тест 2026 уже просмотрен: дальнейшие изменения после его анализа нельзя называть
   разработкой на полностью неизвестном тесте. Сохранять этот результат как исходный ориентир,
   новые решения выбирать по внутренним временным периодам и затем ждать внешней проверки.
2. **Обосновать последствия действий.** Подтвердить карту 3–5 управляющих тегов, единицы,
   пределы и задержки. Добавить ограниченную модель последствий изменения режима гидроочистки
   и влияние АВТ. Проверять ее отдельно от обычного прогноза; перестановка входа CatBoost не
   доказывает причинный эффект. Получить остальные спецификации и условия смешения.
3. **Сделать демонстрацию понятной.** Экран с временной шкалой, источниками и возрастом данных,
   прогнозом, реальными оценками агентов, сравнением действий и причинами запрета. Показательные
   эпизоды выбирать по доступной на тот момент информации; результат раскрывать после решения.
   Подключить готовые расчеты и журналы, не переписывать их в интерфейсе.

## Чего пока нет

Нет пользовательского интерфейса, подтвержденного управления АВТ/гидроочисткой, реальных условий
смешения, оценки остальных свойств топлива, полноценных показателей оборудования/катализатора,
нескольких временных внешних тестов и измеренной экономии. ВАК не используется из-за неоднозначностей.
Глобальная оптимальность не заявляется: поиск долей с шагом 5 п.п., расхода с шагом 10 т/ч.
Рекомендации всегда имеют `commercial_release_allowed=false`.

## Проверка

Тесты проверяют отсутствие будущего в признаках, задержку ЛИМС, границы временных периодов,
зависание ПАК, конфликтующие дубликаты, запреты, пересчет, отсутствие лишних изменений,
невалидные прогнозы, калибровку и повторяемость. Хеши исходников/кода/зависимостей сохраняются.
Исходники task не изменены; коммитов, публикации и сообщений организаторам не было.

## Продолжение: отдельный риск и независимая проверка

После просьбы «продолжай» добавлен `risk.py`: пороги ПАК/ЛИМС, логистическая модель,
CatBoost с ПАК и без ПАК. Выбор на validation по обнаруженным превышениям при бюджете
ложных тревог 20%; затем порог замораживается по calibration. Доля тревог считается среди
лабораторных проб без превышения, а не по времени работы установки.

На 226 общих тестовых анализах, содержащих 33 превышения:

- Выбранный простой порог ПАК: 16/33 найдено, ложные тревоги 60/193 (31.1%).
- CatBoost: 12/33 найдено, ложные тревоги 39/193 (20.2%).
- Логистическая модель: 28/33 найдено, но ложные тревоги 130/193 (67.4%).

Ни один результат не оправдывает заявление о готовом надежном предупреждении.
Бюджет, выполненный на calibration, переносится на 2026 неточно. Выбор модели не изменяли
по этим тестовым результатам. Дополнительная оценка риска подключена к журналам и резервному
режиму; отсутствие тревоги не отменяет ограничений серы. Score не называется вероятностью.

Пользователь попросил субагентов средней мощности, предпочтительно GPT-5.6 Luna. Два Luna
проверили риск и обработку данных. Исправлены молчаливое удаление невалидных измерений
и принятие отрицательной доли пропусков. Вывод одного проверяющего про ошибку порога
перепроверен и отклонен: np.nextafter корректен; тест исправлен на контракт, а не частную реализацию.

30 тестов проходят: дополнительно проверяются неизменность выбора/порогов при изменении
только test, граница доступности самой модели, отказы до вычисления прогноза при старых данных
и невозможность отменить ограничение качества низкой оценкой риска.
