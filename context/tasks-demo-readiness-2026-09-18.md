  повтор теперь по контракту не делается.

### R11. `prepare()` мутирует маску на месте

- `infrastructure/response/estimate.py:56-58`: `floor_rows = hot` — это ссылка, а `&=` в pandas
  меняет объект на месте, поэтому `hot` усекается по `feed_floor_until`, и `running` на `:60`
  считается по усечённой маске. Замер на реальных данных, τ = 2026-01-01: `running` 150 388
  вместо 177 560, `n_rows` 49 069 вместо 49 105, β −0.4226 против −0.4227.
- На опубликованное β влияние 0.0001, но докстринг функции (`:47`) утверждает обратное,
  возвращаемый `f.running` неверен для любого читателя, а новый тест
  (`tests/test_response_estimate.py:63-72`) проверяет только `attrs["feed_floor"]` и это не ловит.
- **Статус: готово.** `floor_rows = hot & (index <= until)` — новый объект, `hot` не меняется;
  `feed_floor_until` стал обязательным (без него — `ValueError`, прежнее поведение с утечкой недоступно
  молча). На реальных данных при τ = 2026-01-01: `running` 177 560 (было 150 388), `feed_floor` 133.457
  без изменений. Артефакт пересобирается в R12 (`train`).

- **Статус: готово.** `estimate_response` хранит части по τ и считает `drift` по частям основной оценки
  (`train_end`); `tau_grid` принимает индекс без временного DataFrame. Выполнены `train`, `snapshot --all`,
